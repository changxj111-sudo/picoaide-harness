## 一、上游菜单在原生材质窗口上不再半透明

- **现象**：侧栏「视图选项」等上游菜单打开后像一层透明膜，下面的会话列表/桌面直接透上来；
  在 Windows Mica、macOS vibrancy 等原生材质窗口上更明显，2.8.2 正式版也有用户反馈。
- **根因**：上游菜单材质是「半透明填充 + backdrop-filter」，窗口为原生材质让路（透明背景、
  左栏 surface transparent）。`backdrop-filter` 只能采样页面自身的绘制结果；透明合成面上
  没有实底时 Chromium 不再产出模糊，菜单只剩约 45–58% 的填充。上游本来就为 macOS 准备了
  `[data-menu-backing]` 实底，但 CSS 只在 `html[data-platform=darwin]` 打开；桌面壳使用
  `data-dsh-desktop-mode` 标记自己，从未设置 `html[data-platform]`，所以这条兜底在所有平台
  都 `display:none`。
- **修复**：在高级外壳样式表里按桌面模式标记打开同一个上游 `[data-menu-backing]`，三个平台
  一起生效；位置沿用上游 CSS anchor，不写上游哈希类名。菜单材质仍是半透明 + 模糊，只是
  背后多了一层可模糊的实底。
- **覆盖范围**：所有使用上游 `MenuSurface` 的菜单（视图选项、账户菜单、设置下拉、右键菜单等），
  不只是「视图选项」。
- **验证**：新增 `tests/menu-material-backing.spec.ts` 与真实合成探针；E2E 新增「视图选项」
  菜单与背板矩形对齐断言（菜单/背板 x、y、宽、高误差 ≤2px）。

## 二、继承 v2.8.3-beta.4 的「更多」修复

- 左下角只保留产品自己的一个「更多」；官方账户菜单触发行隐藏。
- 「设置」作为最后一项并入「更多」浮层。
- 「更多」浮层使用实底 `bg-base`，不再半透明。

## 已知限制

- 本版只修界面；beta.3 的能力与限制不变：旧 cron 任务不迁移；思考过程翻译默认走 Bing，
  涉及敏感内容时不要展开思考过程。
- 原生材质窗口的模糊效果依赖 Chromium 合成；修复只保证菜单背后有不透明实底，不改变
  上游毛玻璃视觉。

## 升级与回滚

- 服务端：取本版镜像附件，按 `docs/deploy/AI-DEPLOY.md` 升级；升级前必须备份。
- 客户端：随服务端镜像分发，员工从自己登录的服务器取包。
- **回滚**：本版无数据库迁移，保留上一版镜像 tag 切回即可；客户端重装 beta.4 包。

- **迁移清单（机器可读锚点，供 `scripts/check-release-notes-migrations.mjs` 与 `git diff` 对拍）**：无
